* **Identified Ambiguities / Assumptions:**
  1. **Zero-Robolectric Pure JVM Worker Testing (`TemperatureCheckWorker`)**: `TemperatureCheckWorker` currently mixes pure business orchestration (permission check -> current city lookup -> weather refresh -> threshold evaluation -> notification / alert reset) directly inside an Android `CoroutineWorker` with `android.util.Log` calls, which previously forced `TemperatureCheckWorkerTest` to use `RobolectricTestRunner`, `ApplicationProvider`, `TestListenableWorkerBuilder`, `androidx.work.testing`, and `androidx.test.core`. Per `testing-setup` Step 4 (*Refactor for Testability*) and §3.1 (*Robolectric reserved strictly for Roborazzi preview rendering*), we extract the pure Kotlin orchestration into `TemperatureCheckCoordinator` (`@Inject constructor(...)` in `app/.../framework/worker/`) and make `TemperatureCheckWorker` a thin `@HiltWorker` adapter (also properly rethrowing `CancellationException`). This eliminates Robolectric from every non-Roborazzi test in the repository and allows removing `androidx.work.testing` and `androidx.test.core`.
  2. **Pure JVM `FavoritesDetailViewModelTest`**: `FavoritesDetailViewModel` previously required `@RunWith(RobolectricTestRunner::class)` solely because `savedStateHandle.toRoute<FavoritesScreens.FavoritesDetail>().cityName` invokes Android `Bundle`/`Uri` stubs inside `androidx.navigation:navigation-common`. Navigation Compose already stores route arguments by parameter name in `SavedStateHandle` (`"cityName"`), so reading `savedStateHandle.get<String>(CITY_NAME_ARG).orEmpty()` preserves exact runtime behavior with zero signature changes (zero Test-Induced Design Damage) while enabling pure JVM testing.
  3. **Zero `mockkStatic(Log::class)` in `CityWeatherViewModelTest`**: `CityWeatherViewModel.kt:189` is the sole `android.util.Log` call in the entire `ui/` package. Removing that stray debug `Log.d` removes `android.util.Log` from the ViewModel layer and removes the only static-mock dependency in `CityWeatherViewModelTest`.
  4. **Full Manual Fakes & `mockk` Removal**: Inspection confirmed that 100% of dependencies injected into tested Repositories, UseCases, ViewModels, and `TemperatureCheckCoordinator` are pure Kotlin interfaces (`AccountService`, `AuthLocalDataSource`, `AuthRepository`, `CityWeatherRepository`, `RemoteConfigRepository`, `LocationRepository`, `PermissionRepository`, `PermissionChecker`, `NotificationService`, `SystemService`) or pure Kotlin UseCases wrapping those interfaces. No tested class touches a final platform class (like `FirebaseAuth` or `FirebaseRemoteConfig`). Therefore all tests move to deterministic hand-written `Fake*` implementations and unused `libs.mockk` is removed from `:app`, `:usecases`, `:data`, and `libs.versions.toml`.
  5. **Budget Framing for Cleanup Slice**: While `testing-setup` §3.2 caps *new* feature slices at `0–6 @Test` total, this slice is a repository-wide test cleanup that **reduces** the existing suite from **63 `@Test` methods** (`45` unit + `17` legacy screen screenshot + `1` instrumented) and **81 committed PNGs** down to **25 cohesive pure JVM `@Test` methods** (`1–3` per class across 9 retained classes, net `-38 @Test`) and **36 deterministic Design System Roborazzi PNGs** (net `-45 PNGs`), introducing `0` new feature test classes.
  6. **Cross-OS Roborazzi Stability (Windows Local Dev vs `ubuntu-latest` CI)**: Git history and Design System CI runs confirm that `63/64` Windows-recorded Design System PNGs already passed on `ubuntu-latest` using `robolectric.pixelCopyRenderMode = "hardware"` and bundled Roboto Flex resources. The single CI failure (`MmWeatherInfoPreview.Foldable_Landscape`) was caused by Coil 3's `.crossfade(enable = true)` animation inside `MmWeatherInfo.kt` during snapshot capture (combined with the redundant `Foldable_Landscape` device preview). Disabling crossfade when `LocalInspectionMode.current` is `true` fixes the root cause without changing runtime behavior. No custom `ComposePreviewTester` threshold override is added prematurely unless `ubuntu-latest` CI flags a real sub-pixel anti-aliasing diff on the regenerated 36-PNG baseline.

## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Establish a fast, deterministic, low-maintenance testing and visual-regression baseline before executing the core modernization features (`domain-error-contract` onward). Specifically:
1. Retire all forbidden legacy tests (`7` screen `*ScreenshotTest.kt`, `17` screen PNGs, `ExampleInstrumentedTest.kt`, trivial `MarkCityAlertNotifiedUseCaseTest.kt`) and unused test dependencies (`androidTestImplementation`, `androidx.work.testing`, `androidx.test.core`, `androidx.junit`, `mockk`).
2. Trim and stabilize the Design System Roborazzi baseline (`@MmDevicePreview` reduced from 6 devices to Phone + Tablet; `MmButton` consolidated from 4 previews to 1 comprehensive preview; `MmWeatherInfo` crossfade disabled in `LocalInspectionMode`; clean 36-PNG baseline regenerated and verified).
3. Refactor all 9 retained unit test classes (`:app` and `:usecases`) to pure JVM, `1–3` cohesive `@Test` methods per class, shared `MainDispatcherRule`, and hand-written in-memory `Fake*` implementations.
4. Rewrite `docs/testing_strategy_guide.md` to serve as an accurate Single Source of Truth aligned with `testing-setup` v2.4.0 and `design-system-governance` §4.

### Non-Goals
* Do **NOT** introduce `DomainError` or migrate away from `CustomError` / `CustomErrorFlow` (owned by `domain-error-contract`).
* Do **NOT** change weather theme palettes, typography sizes, or `Mm*` visual styling beyond the preview consolidation and `LocalInspectionMode` crossfade fix (owned by `dynamic-weather-theme-tokens` and `design-system-components-alignment`).
* Do **NOT** modify `LoginViewModel` / `SignUpViewModel` / `CityWeatherViewModel` / `FavoritesViewModel` business flows or remove the legacy `delay(2000.milliseconds)` in auth ViewModels (owned by `auth-splash-login-overhaul` and `auth-signup-terms-overhaul`).
* Do **NOT** add Robolectric screen tests, Espresso tests, `androidTest` tests, or new unit tests for untested legacy layers (e.g., `:data` mappers or Room DAOs, which belong to their respective modernization slices).
* Do **NOT** remove `TestMeteoMartoApp.kt`, `app/src/test/resources/robolectric.properties`, `robolectric`, `roborazzi.*`, `testImplementation(platform(libs.androidx.compose.bom))`, `testImplementation(libs.androidx.ui.test.junit4)`, or `debugImplementation(libs.androidx.ui.test.manifest)` — all are required by Roborazzi's automated Design System Compose `@Preview` scanner.
