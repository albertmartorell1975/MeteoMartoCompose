## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Align the entire MeteoMarto Design System component library (`ui/designsystem/components/`) and its Material 3 container/surface color wiring (`ui/designsystem/foundation/`) with `DESIGN.md`, `design-system-governance`, `compose-modifier-and-layout-style`, `edge-to-edge`, and `kotlin-style`. Every stateless `Mm*` component will respect all 5 KISS palettes with verified WCAG AA contrast, enforce `>= 48.dp` interactive touch targets, support RTL and 200% font scaling without clipping, avoid hardcoded root layout constraints, and be locked by a deterministic 60-PNG Roborazzi baseline and zero-warning Dokka reference.

### Non-Goals
* Do **NOT** rebuild or redesign application screens (`SplashUI`, `LoginScreen`, `SignUpScreen`, `TermsScreen`, `CityWeatherScreen`, `FavoritesScreen`, `FavoritesDetailScreen`, `HighTemperatureAlertScreen`) or unify `AppState` / `NavHost` routing (owned by `navigation-shell-unification` and downstream screen slices). Only minimal 1-line call-site modifier/host compatibility edits are permitted outside `ui/designsystem/`.
* Do **NOT** modify `AndroidManifest.xml` (`adjustResize`), `MainActivity.kt`, legacy `ui/theme/*.kt`, `res/values/dimens.xml`, or `:domain` / `:data` / `:usecases` modules.
* Do **NOT** add Robolectric functional tests, `MockK`, `src/androidTest/`, or screen-level `*ScreenshotTest.kt` files (`CONSTRAINTS.md` #11, #18).
* Do **NOT** add KDoc comments (`/** ... */`) or author `docs/design-system.md` during Stage 2 implementation (strictly deferred to Stage 4 `workflow-documenter` and Stage 5 `workflow-orchestrator`).

### Job Story
When implementing any MeteoMarto screen across static neutral flows or dynamic weather conditions,
I want every stateless `Mm*` component and Material 3 container role to follow `DESIGN.md` tokens, accessible touch targets, RTL mirroring, 200% font scaling, and caller-owned modifier composition with verified Roborazzi snapshots,
so downstream screen overhauls can compose consistent, contrast-safe, and adaptive UIs without fighting hardcoded sizes, leaking purple M3 defaults, or breaking visual regression CI.
