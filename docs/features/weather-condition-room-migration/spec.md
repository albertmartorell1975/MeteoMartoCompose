* **`module_topology`:** `Layer-Based (:domain -> :usecases <- :data -> :app)`
* **Objective:** Introduce a pure `:domain` `WeatherCondition` model mapped deterministically from OpenWeather condition IDs (`weather[0].id`), derive nocturnal state (`isNight`) deterministically from OpenWeather payloads, persist both `weatherConditionId` and `isNight` in Room via an explicit non-destructive `Migration(2, 3)` with exported Room schema verification (`exportSchema = true`), keep Room refresh/favorite SSOT mappers consistent, remove `.fallbackToDestructiveMigration(true)` + unused imports in `AppProvideModule`, and complete the queued PR #7 follow-up cleanups (`AuthRoomDataSource.kt`, `LocationLocalServerDataImpl.kt`, and unused `Result.fold` in `domain/.../Result.kt`).
* **Identified Ambiguities / Assumptions:**
  1. **Computed `weatherCondition` Property on `CityWeatherDomain`:** `CityWeatherDomain` stores `weatherConditionId: Int = 0` and `isNight: Boolean = false` and exposes `val weatherCondition: WeatherCondition get() = WeatherCondition.fromOpenWeatherId(weatherConditionId)`. Computing `weatherCondition` guarantees `weatherConditionId` and `weatherCondition` can never drift out of sync. Retaining backward-compatible default values (`= 0`, `= false`) on `CityWeatherDomain` (matching its existing 9 defaulted properties) avoids unrelated churn in Design System previews (`MmWeatherInfo.kt` — preserving all `36/36` Roborazzi PNGs untouched) and legacy screens/tests (`WIP=1`). In contrast, the new columns on `@Entity CityWeather` declare NO Kotlin constructor defaults (only Room `@ColumnInfo(defaultValue = "0")`), forcing compile-time explicit mapping in `CityMapper`.
  2. **Deterministic `isNight` Precedence (`CONTEXT.md` & `docs/domain-model.md`):** `resolveIsNight(iconCode, dt, sunrise, sunset)` inspects the raw OpenWeather `weather.firstOrNull()?.icon` *before* URL construction (`@2x.png`): trimmed lowercase suffix `"n"` -> `true`, `"d"` -> `false`; only when the icon is missing/blank/lacks a `"d"`/`"n"` suffix does it fall back to `dt < sunrise || dt > sunset` (when `dt > 0 && sunrise > 0 && sunset > 0 && sunrise < sunset`), otherwise defaulting safely to `false`.
  3. **Room Schema Parity (`v2 -> v3`) Without Destructive Fallback:** Annotating `weatherConditionId: Int` and `isNight: Boolean` on `@Entity CityWeather` with `@ColumnInfo(defaultValue = "0")` ensures fresh-install `CREATE TABLE` DDL and `MIGRATION_2_3` `ALTER TABLE ... ADD COLUMN ... INTEGER NOT NULL DEFAULT 0` produce identical SQLite `TableInfo` definitions. Enabling `exportSchema = true` with KSP `arg("room.schemaLocation", "$projectDir/schemas")` generates a version-controlled `3.json` schema snapshot verified by pure JVM tests without Robolectric or `androidTest`.
  4. **Pure JVM Verification of `:domain` and Room Migration (`CONSTRAINTS.md`):** Adding `testImplementation(libs.junit)` to `domain/build.gradle.kts` enables pure JVM `:domain:test` without adding any runtime/implementation dependencies to `:domain`. Room migration integrity is verified purely on JVM via a manual `SupportSQLiteDatabase` SQL recorder paired with structural assertions against KSP-generated `app/schemas/.../3.json`, plus live SQLite execution on emulator during Validator Level 4.
* **Necessary Questions:** None — all requirements clarified from `CONSTRAINTS.md`, `CONTEXT.md`, `docs/domain-model.md`, `DESIGN.md`, and inspected source files.

## 2. Goal, Non-Goals & Acceptance Scenarios

### Goal
Ensure `MeteoMartoCompose` accurately classifies OpenWeather conditions (`SUNNY`, `RAIN`, `BASELINE`) and nocturnal telemetry (`isNight`) and persists both attributes in Room as the Single Source of Truth (SSOT) across fresh inserts, subsequent weather refreshes, favorite toggles, and `v2 -> v3` app upgrades without wiping existing local data. Simultaneously complete the queued PR #7 data/domain hygiene follow-ups (`AuthRoomDataSource`, `LocationLocalServerDataImpl`, and unused `Result.fold`).

### Non-Goals
* Do **NOT** implement the five KISS `SimpleWeatherPalette` theme tokens, Roboto Flex typography changes, WebP assets, or dynamic screen theming (owned by `dynamic-weather-theme-tokens` and `city-forecast-dynamic-screen`).
* Do **NOT** modify `MmWeatherInfo.kt`, any Design System component/preview, or any of the `36` Roborazzi snapshot PNGs under `app/src/test/snapshots/`.
* Do **NOT** modify `CheckTemperatureThresholdUseCase`'s `>=` vs `>` comparison (owned by `high-temp-alert-screen-overhaul`) or refactor `CityWeatherDomain`'s existing pre-modernization fields (`weatherDescription`, `weatherIcon`, `rain`) into non-nullable types.
* Do **NOT** add Robolectric unit tests (`RobolectricTestRunner`), `MockK`, `src/androidTest/`, or `room-testing` instrumentation dependencies.

### Job Story
When the app fetches live OpenWeather telemetry or upgrades an existing installation with saved favorite cities,
I want OpenWeather condition IDs and nocturnal state (`isNight`) to be mapped deterministically and persisted in Room via a non-destructive schema migration,
so downstream dynamic weather themes always reflect accurate day/night and climate states both online and offline without losing saved user data.

### Acceptance Scenarios

#### Scenario 1: Deterministic OpenWeather Condition ID Mapping (`:domain`)
* **Given** raw OpenWeather condition IDs covering clear sky (`800`), thunderstorm (`200..232`), drizzle (`300..321`), rain (`500..531`), snow (`600..622`), atmosphere (`700..781`), clouds (`801..804`), and unknown/missing codes (`0`, `-1`, out-of-range boundaries)
* **When** `WeatherCondition.fromOpenWeatherId(id)` (and `CityWeatherDomain.weatherCondition`) evaluates each ID
* **Then** `800` maps to `WeatherCondition.SUNNY`, all codes in `200..232`, `300..321`, `500..531`, `600..622` map to `WeatherCondition.RAIN`, and all other codes map to `WeatherCondition.BASELINE`.

#### Scenario 2: Deterministic Nocturnal State (`isNight`) Derivation & SSOT Mapping (`CityMapper` & `CityRoomDataSource`)
* **Given** an OpenWeather `CityWeatherResponse` payload with either an explicit icon suffix (`"01n"`, `"10d"`), a missing/empty `weather` list with valid `dt`/`sys.sunrise`/`sys.sunset` timestamps, or missing timestamps
* **When** `CityWeatherResponse.toRoom()` maps the DTO into `CityWeather`, `CityRoomDataSource.refreshCity(...)` inserts or updates the existing row in Room, and `CityWeather.toDomain()` / `CityWeatherDomain.toRoom()` round-trip the record (including on `switchFavorite`)
* **Then** `isNight` prioritizes icon suffix (`"n"` -> `true`, `"d"` -> `false`), falls back to `dt < sunrise || dt > sunset` when suffix is absent (else `false`), and both `weatherConditionId` and `isNight` are persisted on insert, updated on refresh without overwriting `favorite`/`isAlertNotified`, and preserved on favorite toggle.

#### Scenario 3: Non-Destructive Room `v2 -> v3` Migration & Tracked Schema Export
* **Given** an existing `MeteoMartoDatabase` at schema `version = 2` containing saved `CityWeather`, `User`, and `LocationLocal` rows
* **When** the database opens at `version = 3` through `AppProvideModule` (with `.addMigrations(MIGRATION_2_3)` and zero `.fallbackToDestructiveMigration(...)`)
* **Then** `MIGRATION_2_3` executes non-destructive `ALTER TABLE CityWeather ADD COLUMN` statements for `weatherConditionId INTEGER NOT NULL DEFAULT 0` and `isNight INTEGER NOT NULL DEFAULT 0`, preserving all existing rows, and the exported KSP schema `app/schemas/.../MeteoMartoDatabase/3.json` matches version `3` and both columns' exact affinity, `notNull`, and `defaultValue`.

#### Scenario 4: Queued PR #7 Data & Domain Hygiene Cleanup
* **Given** `AuthRoomDataSource.kt`, `LocationLocalServerDataImpl.kt`, and `domain/.../model/Result.kt`
* **When** auditing coroutine dispatchers and `Result` helpers
* **Then** redundant `withContext(Dispatchers.IO)` wrappers are removed from `AuthRoomDataSource` and `LocationRoomDataImpl` (with `LocationRoomDataImpl.saveLocation` using main-safe `db.withTransaction`), `Result.fold` is removed from `domain/.../model/Result.kt`, and all compilation, lint, and unit test gates pass cleanly.
